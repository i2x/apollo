# วิธีใช้ wiki นี้

## เปิดอ่าน

```bash
cd tools/wiki-viewer
npm install      # ครั้งแรกครั้งเดียว
npm run wiki     # แล้วเปิด http://localhost:4000
```

viewer ใช้**อ่านอย่างเดียว** ส่วนการเขียนให้แก้ไฟล์ `.md` ใน editor ที่ถนัด แก้แล้วกด refresh ในเบราว์เซอร์ก็เห็นผลทันที
หน้าแรกแสดง skill tree, บันไดโปรเจกต์ และผลตรวจกติกา ถ้าแค่อยากตรวจกติกาโดยไม่เปิดเว็บ ใช้ `npm run check`

## หลักการเดียว: ไม่มีหลักฐาน = ยังไม่รู้

อ่านบทความเรื่อง core loop มาสิบบทความ แต่ยังไม่เคยออกแบบ loop แล้วเห็นมันพังตอนเล่นจริง แบบนี้ยังไม่นับว่ารู้
wiki นี้จะนับว่า "รู้แล้ว" ได้ก็ต่อเมื่อมี **evidence** เท่านั้น evidence คือกติกาที่เขียนเองหรือ playtest log ที่เกิดจากการเล่นจริง

## wiki มีสองส่วน

- **`skills/`: skill tree** มี 1 ไฟล์ต่อ 1 concept แต่ละ node บอกว่าต้องรู้อะไรมาก่อน (`requires`) และพิสูจน์แล้วด้วยอะไร (`evidence`)
- **`projects/`: บันไดโปรเจกต์** เป็นเกมกระดาษที่ใหญ่ขึ้นเรื่อยๆ ทุก evidence เกิดขึ้นที่นี่

skill บอกว่า**ต้องเรียนอะไร** ส่วนโปรเจกต์เป็น**ที่ที่ได้เรียนจริง**

## สถานะของ node

| สถานะ | ความหมาย | ใครเปลี่ยน |
|---|---|---|
| `locked` 🔒 | node ใน `requires` ยังไม่ `learned` ครบ | — |
| `learning` 🔄 | เปิดแล้ว มีคำอธิบายกับแบบฝึก | Claude เปลี่ยนให้เมื่อเงื่อนไขครบ |
| `learned` ✅ | มี evidence, เขียนความเข้าใจแล้ว, ตอบคำถามตรวจผ่านแล้ว | **คุณเท่านั้น** |

ย้อนจาก `learned` กลับไปเป็น `learning` ได้เสมอ ถ้าทำโปรเจกต์ถัดไปแล้วพบว่ายังไม่เข้าใจจริง ถือเป็นเรื่องปกติ ให้เขียนเหตุผลไว้ในส่วน "คำถามที่ยังค้าง"

## ใครเขียนส่วนไหน

| ส่วน | คนเขียน |
|---|---|
| คืออะไร | Claude (สั้น ไม่เกิน 1 ย่อหน้า) |
| แบบฝึก | Claude |
| **ความเข้าใจของผม** | **คุณเท่านั้น** ใช้คำพูดของตัวเอง หลังทำแบบฝึกแล้ว |
| คำถามที่ยังค้าง | ใครก็ได้ |
| คำถามตรวจ | Claude ถาม คุณตอบต่อท้ายแต่ละข้อ |
| กติกาเกมในโปรเจกต์ | **คุณเท่านั้น** Claude วิจารณ์และตั้งคำถามได้ แต่ไม่เขียนแทน |

## หนึ่งรอบการเรียน

1. **เปิดรอบ:** Claude สรุปว่าอยู่ตรงไหน แล้วเสนอสิ่งที่ควรทำต่อ
2. **Unlock:** node ไหนที่เงื่อนไขครบ Claude จะเปิดให้ และเขียนคำอธิบายกับแบบฝึก
3. **ลงมือ:** ทำ prototype บนกระดาษแล้วเล่นจริง ขั้นนี้ทำนอกคอม
4. **จด log:** จดตาม `_templates/playtest-log.md`
5. **เขียน:** เขียนส่วน "ความเข้าใจของผม"
6. **ตรวจ:** Claude อ่านแล้วตั้งคำถามตรวจ คุณตอบในไฟล์
7. **ปิด:** ถ้าผ่าน คุณเปลี่ยนสถานะเป็น `learned` เอง แล้ว Claude อัปเดตส่วน "ตอนนี้" ในหน้าแรก (`README.md`) และ commit

## การตั้งชื่อไฟล์

- ชื่อไฟล์เป็นภาษาอังกฤษแบบ kebab-case และ**ต้องไม่ซ้ำกันทั้ง wiki** (ยกเว้น `README.md`) เพื่อให้ `[[ชื่อ]]` ชี้ไปไฟล์เดียวเสมอ
- กติกา: `<โปรเจกต์>-rules-v<N>.md` เช่น `dice-duel-rules-v1.md` **ห้ามเขียนทับเวอร์ชันเก่า** ถ้าจะแก้ให้สร้างเวอร์ชันใหม่ เพราะการได้เห็นว่ากติกาเปลี่ยนไปอย่างไรคือบทเรียน
- Playtest: `playtests/<โปรเจกต์>-<YYYY-MM-DD>-v<N>.md` โดย `vN` คือเวอร์ชันกติกาที่ใช้เล่น ถ้าเล่นวันเดียวกันหลายครั้งให้เติม `-2`, `-3` ต่อท้าย
- ลิงก์ไปโปรเจกต์ให้ใช้ชื่อโฟลเดอร์ เช่น `[[01-dice-duel]]`

## เริ่มไฟล์ใหม่

ก๊อปไฟล์จาก `_templates/` ไปวางแล้วเปลี่ยนชื่อ โฟลเดอร์ที่ขึ้นต้นด้วย `_` ไม่นับเป็นหน้า wiki
ใน frontmatter ช่อง `evidence` ให้ใส่ path นับจาก `wiki/` เช่น `projects/01-dice-duel/playtests/dice-duel-2026-10-01-v1.md`
